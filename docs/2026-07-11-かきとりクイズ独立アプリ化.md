# かきとりクイズ（手書き記述式）の追加と独立アプリ化 — 実装の記録

- 日付: 2026-07-11
- 依頼: 「漢字ドリルで送りがなが書いてあって漢字にする問題を作成して。まずは2年生だけで良い」
- 結論: **7つ目のアプリ `kaki/index.html`（かきとりクイズ）として公開済み**。□に入る漢字を手書きして、こたえ合わせ→自分で⭕❌をつける自己採点式。出題はいまは2年生配当のみ。

---

## 1. 何を作ったか（ひとことで）

紙の漢字ドリルの「書き問題」をアプリにしたもの。「あかるい」＝ □るい のように読みと送りがなを見せて、□に入る漢字（明）を手書きで書かせる。書いたら「👀 こたえ合わせ」で正解を表示し、自分の字とくらべて「⭕かけた／❌まちがえた」を本人が選ぶ。

## 2. 経緯（3段階で形が変わった）

1. **最初は4択**（かん字をえらぶ）で送りがなアプリ内のモードとして実装。全133語で選択肢の健全性を機械チェックして検証まで完了。
2. **途中指示「記述式に変更できますか？」**を受け、方式を確認のうえ**手書きキャンバス＋自己採点**に置き換え（4択は廃止）。
3. **翌日のフィードバック「既存クイズの中に含まれているのは違う。TOPページに追加してほしい」**を受け、送りがなアプリからモードを取り除いて元に戻し、**独立アプリ `kaki/` に切り出してトップのメニューに追加**した。

教訓：この種の「新しい問題形式」は、最初から独立アプリとして作るのが本ポータルの設計（1クイズ1アプリ）に合う。既存アプリへのモード追加は画面の分岐が増えるわりに、利用者（家族）からはアプリ一覧に見えず発見しにくい。

## 3. 部品と仕組み（非エンジニア向け）

- **問題データは手作りしていない**。漢字マスタ `shared/kanji-db.js` の訓読み（例 `明: あか(るい)`）を `parseOkurigana` で「読み・語幹・送りがな」に分解して自動生成。漢字をDBに足せば問題も自動で増える。
- **2年生しばり**は `kaki/index.html` 内の `KAKI_POOL = ALL_WORDS.filter(w => w.grade === 2)` の1行。学年を広げるときはここを変えるだけ（2年生は133語・64字）。
- **手書きマス**は `<canvas>`。マウス・指・ペンで書ける（pointerイベント）。ドリルのマスと同じ薄い十字ガイド付き。「🧽 かきなおす」で消せる。手書きの自動認識はあえて入れていない（子どもの字の認識精度が不安・認識ライブラリ同梱はオフライン配布と相性が悪い）。採点は本人の自己申告。
- **別解の併記**：同じ読み・同じ送りがなで別の漢字も正解になる語が29組ある（あう＝会う/合う、はかる＝計る/図る 等）。こたえ合わせで「※ 合う と書いても ⭕だよ」と出して、正しく書けたのに❌にしてしまう事故を防ぐ。
- **記録**は共有エンジン QuizCore に合流：正解で図鑑・称号・メダル・累計にカウント（全アプリ合算）。アプリ専用の領域は `store.kakiWrong`（まちがい復習）と `store.kakiDaily`（デイリー連続日数）。モード時代にまちがえた記録もキー名が同じなのでそのまま引き継がれる。
- **トップページ**：基礎クイズ列の4つ目（✍️・紫）。上級3クイズ（部首・画数・四字熟語）の解放条件は従来どおり「同じ読み・送りがな・音訓で各30問正解」のままで、かきとりは条件に**入れていない**（案内文だけ「上の3つ」→クイズ名の列挙に修正）。かきとりの正解数は `appCorrect.kaki` に別途たまるので、将来条件に入れることもできる。

## 4. 検証（実行したこと）

- `node validate.mjs` → exit 0（既存データ検証すべて合格）
- 2年生全133語 × 20回の問題生成を機械チェック（4択時代：正解が選択肢に必ずある・別解が誤答に混ざらない）／記述式化後は別解リストの生成を全語で確認
- 実ブラウザ（Chrome DevTools 経由）で通し確認：出題→canvas描画→こたえ合わせ→⭕採点（図鑑・累計に反映）→❌採点（kakiWrongに追加）→前へ/次へで状態再現→復習が手書き形式で再出題→デイリー10問クリアで⭐3とストリーク加算→送りがなアプリが元の表示に戻っている。コンソールエラー0
- deploy 後 CI（validate.yml）success、本番 `…/kaki/index.html` HTTP 200
